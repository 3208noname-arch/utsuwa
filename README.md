# utsuwa

Obsidian の Vault に置いた md で、性格を持つエージェントを Discord の雑談に住まわせるハーネス。

判断、参照、記録はコードと判定モデル（TypeSafe の Jev）が決め、LLM には文章だけを書かせる。
LLM に輪を回させないので、会話用の LLM が読む量を小さく保てる。

## 1人のエージェント＝1つのフォルダ

```
<エージェント>/
├─ Agents/              人が直す（ハーネスは書かない）
│   ├─ SOUL.md          人格
│   ├─ AGENTS.md        返事の決まりと、渡される節の一覧、出力の形
│   ├─ RECORDER.md      記録の決まり（記録用の LLM だけが読む）
│   ├─ SCHEDULE.md      毎週の予定と臨時の予定（表）
│   └─ config.yaml      チャンネル、モデル、記憶の種類。鍵は書かない
├─ 00 Diary/            日記（夜の整理で書く）
├─ 01 Lessons/          記憶。種類ごとのフォルダに1件1ノート、Base で一覧
├─ 02 State/            数値の状態（JSON）
└─ 03 Logs/             会話と評価の原本（JSONL）
```

`02 State/` と `03 Logs/` は、`--data` で Vault の外（動かすマシンの中）に置ける。
Vault には人が読み書きする md だけを置き、頻繁に書く JSON と友人の発言の原本を同期に乗せないため。
見本は全部を1つのフォルダに入れてある。

見本は [`template/あかり/`](template/あかり/)（架空の人物）。
フォルダを Vault に写し、`Agents/` を書き換えれば、別のエージェントになる。
Obsidian で md を直すと、次に読む時から効く（再起動は要らない）。

## 流れ

返事の流れ

1. **判断する**（規則と Jev 1回）：返す、黙る、後で返す、どの型で返すか。言いたいことのキューに積む
2. **窓口が1つ選ぶ**：喋る入口（返事、後で返す、放置を拾う、自分から話題、抜ける一言）は多くても、出すのは1回に1つ
3. **文脈を組む**：Jev が記憶の種類を絞り、その種類の表の全行から関係する行を選ぶ（キーワードで候補を集めない）
4. **書く**：会話用の LLM が `SOUL.md`＋`AGENTS.md`＋選ばれたデータだけを読み、2〜3案を一度に書く
5. **確かめる**：正規表現の検査と Jev の立場チェックで1案を選ぶ
6. 書くのは、気付くまでの間を待つ間に済ませる。その間に会話が進んだら、Jev が「通す、書き直す、黙る」を選ぶ

記録の流れ

1. **記録するか**（Jev）：発言の後の6件か10分を待ち、前後と一緒に読んで、記憶の種類を選ぶ（思い出、常識、スマホのメモ、その他、反省、しない）
2. **記録用 LLM が書く**：`RECORDER.md` だけを読む。スマホのメモの本文は LLM に書かせず、送られたものを写す
3. **保存する**（コード）：プロパティを付けて検査し、`01 Lessons/` に1件1ノート
4. **夜の整理**：似た記憶を Jev が比べ、古い方を `status: inactive` にする（消さない）。日記を書く

エージェント自身の発言は、記憶の元にしない（作り話が事実として定着するのを防ぐ）。

## 動かす

```bash
pip install -r requirements.txt
cp .env.example .env               # 鍵を書く
python -m harness "template/あかり" --check   # Discord に繋がずに、フォルダを読めるか確かめる
python -m harness "/path/to/Vault/12 AIたち/あかり" --data /var/lib/utsuwa/あかり --env .env
```

## 人格の部品

`personas/` の下に、人格ごとの部品を置く（`config.yaml` の `persona` で選ぶ）。

- `basic`：体も気分も持たない。今の様子は予定だけで決める
- `nagi`：体（眠気、空腹、気力、財布）、予定から決まる今の様子、気分（居心地）、話題の好き嫌い、混ざり方を居心地の予想で選ぶ、好感度、怒りと謝り、呼び名。規則は `personas/nagi/engine/`
  - 予定（講義、バイト、臨時の休み）は `SCHEDULE.md` から読む。見本は `personas/nagi/SCHEDULE.example.md`
  - 決まりの値（怒りの増え方、好感度の増減、体の進み方など）は `config.yaml` の `rules:` で上書きできる。見本は `personas/nagi/config.example.yaml`、今の既定値は `python -m personas.nagi` で出る
  - 気分、好感度、怒り、呼び名は、本体の「後で読む」の Jev 1回で読む（記録するかと同じ呼び出し）
  - 今やったこと、奢ってもらったこと、口にした好き嫌いは、送った返事を Jev が読んで決める（会話用の LLM には書かせない）

部品は `harness/persona.py` の差し込み口だけを書く。どれも省略できる。
数値の状態は部品が持ち、会話用の LLM には言葉に直して渡す。
